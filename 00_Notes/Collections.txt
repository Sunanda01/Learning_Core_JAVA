A. LIST
1. ArrayList:
ArrayList is a resizable array implementation of List.
- Problem with normal array: 
    - Fixed size
    - Cannot easily grow/shrink
    - Manual resizing is required

- Properties:
    - Maintains insertion order       
    - Allows duplicates               
    - Allows null                     
    - Dynamic/resizable               
    - Fast random access (get)     
    - Not thread-safe by default       

- Traversing an ArrayList
    1. Enhanced for loop — most common
        for (int n : nums) {
            System.out.println(n);
        }

    2. Normal for loop: Useful when you need the index:
        for (int i = 0; i < nums.size(); i++) {
            System.out.println(nums.get(i));
        } 

2. Stack: It is a LIFO (Last In, First Out) data structure.
  - pop() vs peek()
    - stack.peek() => only looks at the top.
    - stack.pop() => returns AND removes the top.

3. LinkedList: doubly linked list implementation of the List interface.
    → Nodes connected using links
    → Slow index access
    → Insertion/removal is efficient when you already have the node/position

B. Queue [FIFO]
        Deletion [front_side] <---- |===============| <---- Addition [rear_side]

1. LinkedList: can implement the Queue interface, so we can use it as a FIFO (First In, First Out) data structure.

    - Methods available
    | Method      | Purpose              | Empty/Failure behavior                   |
    | ----------- | -------------------- | ---------------------------------------- |
    | `offer(x)`  | Add element          | Returns `false` if insertion fails       |
    | `add(x)`    | Add element          | Throws exception if insertion fails      |
    | `poll()`    | Remove front element | Returns `null` if queue is empty         |
    | `remove()`  | Remove front element | Throws `NoSuchElementException` if empty |
    | `peek()`    | View front element   | Returns `null` if queue is empty         |
    | `element()` | View front element   | Throws `NoSuchElementException` if empty |
    | `size()`    | Number of elements   | —                                        |
    | `isEmpty()` | Check whether empty  | —                                        |

2. PriorityQueue
- not a sorted collection.
- internally maintains a structure so that the highest-priority element is available at the head.
- By default: smallest → highest priority

3. ArrayDeque
- double-ended queue (Deque) implemented using a resizable array.
- allows insertion and removal from both ends.
- Can be used as Stack and Queue
- Resizable
- Does NOT allow null elements
- Not thread-safe
  
    Front                  Rear
    ↓                      ↓
    [10] → [20] → [30] → [40]
    ↑                      ↑
    addFirst()           addLast()
    removeFirst()        removeLast()

    | Method          | Purpose            |
    | --------------- | ------------------ |
    | `addFirst(x)`   | Add at front       |
    | `addLast(x)`    | Add at rear        |
    | `removeFirst()` | Remove from front  |
    | `removeLast()`  | Remove from rear   |
    | `peekFirst()`   | View front         |
    | `peekLast()`    | View rear          |
    | `size()`        | Number of elements |
    | `isEmpty()`     | Check empty        |

C. Iterator: It is used to traverse/iterate through elements of a Collection one by one.  
- useful when we want to traverse and safely remove elements while iterating.

- Important Interator Method
    | Method      | Purpose                                       |
    | ----------- | --------------------------------------------- |
    | `hasNext()` | Checks whether another element exists         |
    | `next()`    | Returns the next element                      |
    | `remove()`  | Removes the last element returned by `next()` |

- Enhanced for vs Iterator 
    - For simple traversal, enhanced for is usually cleaner.
    - Use an Iterator when we need explicit traversal control, especially safe removal during iteration.

D. Set
1. HashSet: Set implementation used when we want to store unique elements.
- No Duplicates               
- Doesn't maintain insertion order 
- Allows one null           
- Fast add/search/remove    
- Not Thread-safe               

> Why are duplicates removed?
    HashSet internally uses hashing. Java calculates a hash for 20 and uses it to determine where to store the element. 
    - When you again do: nums.add(20); 
    - it checks whether an equivalent element already exists.

    | Feature         | ArrayList          | HashSet            |
    | --------------- | ------------------ | ---------------    |
    | Duplicates      | ✅                  | ❌               |
    | Insertion order | ✅                  | ❌               |
    | Index access    | ✅                  | ❌               |
    | `contains()`    | O(n)               | Average O(1)       |
    | Main use        | Ordered collection | Unique elements    |

2. LinkedHashSet is a Set implementation that gives Unique elements and Insertion order maintained
- LinkedHashSet uses additional links internally to maintain the insertion order, so it generally uses more memory than HashSet.
- No Duplicates              
- Maintains insertion order 
- No Index access              
- Allows one null           
- Average add/search/remove O(1)
- Thread-safe               

3. TreeSet: Set implementation that stores unique elements in sorted order.
- Elements are automatically maintained in sorted order.
- No Duplicates                
- No index access               
- Average add/search/remove  O(log n)
- Dont allow null               
- Not Thread-safe                

> Sets with Custom Classes — equals() & hashCode()
- When storing custom objects in HashSet / LinkedHashSet, Java needs to determine whether two objects are duplicates.
- Important Rule: If: a.equals(b) == true Then: a.hashCode() == b.hashCode()
    but same hashCode ≠ objects must be equal

    equals() → Are these two objects equal?
    hashCode() → Where should this object be looked for?

E. Map
1. HashMap: stores data in key-value pairs.
- Important Properties:
    ├── Key → Value pairs
    ├── Keys are unique
    ├── Values can be duplicated
    ├── One null key allowed
    ├── Multiple null values allowed
    ├── No guaranteed order
    ├── Average put/get/remove → O(1)
    └── Not thread-safe

2. TreeMap: stores data in key-value pairs, like HashMap, but keeps the keys sorted.
- Important Properties:
    ├── Key → Value pairs
    ├── Keys are unique
    ├── Keys are sorted
    ├── Values can be duplicated
    ├── get/put/remove → O(log n)
    ├── Null key → ❌
    └── Not thread-safe

F. Collections: utility class in java.util that provides ready-made methods for working with collections like List, Set, etc.
- Important: Collection is an interface, while Collections is a utility class.   
- Important Methods
    | Method                              | Purpose                       |
    | ----------------------------------- | ----------------------------- |
    | `Collections.sort(list)`            | Sort ascending                |
    | `Collections.reverse(list)`         | Reverse order                 |
    | `Collections.max(list)`             | Find maximum                  |
    | `Collections.min(list)`             | Find minimum                  |
    | `Collections.frequency(list, x)`    | Count occurrences             |
    | `Collections.swap(list, i, j)`      | Swap elements                 |
    | `Collections.binarySearch(list, x)` | Binary search in sorted list  |
    | `Collections.fill(list, x)`         | Replace all elements with `x` |
    | `Collections.shuffle(list)`         | Randomly shuffle              |

G. Sorting Custom Classes: When we have objects of our own class, Java doesn't automatically know which field to sort by.

    Custom Object Sorting
    │
    ├── Comparable
    │   └── Natural/default sorting
    │
    └── Comparator
        └── Custom/different sorting

> Comparable vs Comparator
    |                             | Comparable               | Comparator                   |
    | --------------------------- | ------------------------ | ---------------------------- |
    | Interface                   | `Comparable<T>`          | `Comparator<T>`              |
    | Method                      | `compareTo()`            | `compare()`                  |
    | Sorting defined             | Inside the class         | Outside the class            |
    | Purpose                     | Natural/default ordering | Custom ordering              |
    | Multiple sorting strategies | ❌ Not convenient        | ✅  Covenient               |
    | Example                     | Student → sort by ID     | Student → sort by name/marks |
