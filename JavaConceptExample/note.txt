//JVM, JRE, JDK
JDK => Used to develop Java apps (contains javac)
       Covert source code to byte code
       Contains JRE + development tools
       Acts as an upper layer. 
       Sequence JDK -> JRE -> JVM

JRE => Provides the libraries + JVM required to run Java programs
       Contains JVM and required class libraries (runtime environment)
       JVM is a part of JRE
       
JVM => Executes the byte code
       Converts byte code into machine code using JIT (Just-In-Time compiler)
       Platform dependent, but bytecode is platform independent

- Outer layer of JVM is a virtual layer
- To run Java code, only JRE is needed.
- To write/compile code, you need JDK.

   StringBuffer stringBuffer = new StringBuffer("Hello");

//Static Variable, Method, Block
- Static variable is common for all. Updating the static var will update the value of variable in all place. Belongs to the class, not individual objects.
    *Access* => ClassName.static_variable

- Static Method: Belongs to the class. Can be called without creating an object.
  We can access static var in Static Method directly but we cannot access non-static var in static method directly.
  For using non-static var we need to create object of that class and using dot operator(.) we can access non-static var. Ex: new ClassName().var_name

- Static Block is called only once irrespective of how many times the object of class is created
  Runs once when the class is loaded, before the main method.
  Used for static initialization.
  Useful for initializing static variables when initialization requires multiple statements or logic.
    Syntax for calling Static Block => Class.forName(Class_Name) => forces class loading -> triggers static block

//Exception Handling
- Compile Time Error: Error detected during compilation, before the program runs.
  Ex: int x = "10";   //incompatible types → Compiler stops the program.
- Logical Error: Program runs successfully, but produces the wrong result because the logic is incorrect.
- Runtime Error: Error occurs while the program is running. The code compiles, but crashes/throws an exception during execution.  

- try      → code that may cause exception
- catch    → handles the exception
- throws   → declares that a method may throw exception
- throw    → actually throws an exception

Hierarchy
                  object
                     |
                  Throwable
    -----------------------------------------
    |                                        |
  Error                                   Exception
                                             |
                              --------------------------------
                              |              |                |
                    Runtime Exception     SQLException    IOException
                  [Unchecked Exception]   ------[Checked Exception]---

1. Checked Exception => We must handle. Compiler forces us to handle it or declare it with throws. If we don't handle/declare it → Compile-Time Error.

2. Unchecked Exception => We can handle. Compiler does NOT force us to handle it. These extend RuntimeException. Compiles successfully → when executed → ArithmeticException.

- Ducking Exception: Exception ducking means a method doesn't handle an exception itself; instead, it passes the responsibility to its caller using throws.
Ex:
import java.io.IOException;
class Main {
    static void readFile() throws IOException {
        // Instead of handling IOException here,
        // we pass it to the caller
        throw new IOException("File error");
    }
    public static void main(String[] args) {
        try {
            readFile();
        }
        catch (IOException e) {
            System.out.println(e.getMessage());
        }
    }
}
