//JVM Stack & Heap
Java memory can be broadly understood using Stack and Heap.
JVM Memory
│
├── Stack
│   └── Method calls + local variables + references
│
└── Heap
    └── Objects + instance fields

Example:
class Student {
    int age;
    String name;
}

public class Main {
    public static void main(String[] args) {

        int x = 10;

        Student s = new Student();
        s.age = 25;
        s.name = "Sunanda";
    }
}    

Conceptually:
STACK                          HEAP

main() frame                   Student object
┌───────────────┐             ┌───────────────┐
│ x = 10        │             │ age = 25      │
│ s ────────────┼────────────►│ name ──────────┼──► "Sunanda"
└───────────────┘             └───────────────┘

- Stack → method execution and local variables/references.
- Heap → objects created using new and their instance fields.
- s is a reference variable in the main() stack frame.
- The Student object referred to by s is in the heap.
- age is an int, but because it is an instance field, it is part of the Student object on the heap.
- When a method finishes, its stack frame is removed.
- Objects with no reachable references can later be reclaimed by Garbage Collection (GC).

//Access Modifiers
1. Private => accessible only inside the class where it is declared.
2. Protected => Same package → protected is accessible. Different package → accessible to subclasses
3. Default => can be accessed within the same class and anywhere in the same package. 
              also called package-private access.

                    private   default   protected   public
------------------------------------------------------------
Same Class             YES       YES        YES       YES
Same Package           NO        YES        YES       YES
Different Package
  - Subclass            NO        NO         YES       YES
  - Non-Subclass        NO        NO         NO        YES
------------------------------------------------------------


// toString(), equals(), hashCode()
> toString()
→ Default: ClassName@hex(hashCode())
→ Override when you want meaningful object output

> equals()
→ Default: compares references (this == obj)
→ Override when you want logical/value comparison

> hashCode()
→ Default: object-based hash value
→ Override when equals() is overridden
→ Used by HashMap / HashSet

//Upcasting & Downcasting
Upcasting => Child → Parent, Automatic, Usually safe

Downcasting => Parent → Child, Explicit cast required, Can cause ClassCastException

// Boxing & Unboxing
Boxing: Primitive → Wrapper
Unboxing: Wrapper → Primitive

//Inner Class => class defined inside another class. Can access members of the outer class directly
Outer object → needed to create a non-static inner-class object.

//Anonymous Inner Class 
→ Inner class without a name
→ Created and instantiated at the same time
→ Usually used for one-time implementation
→ Can extend a class or implement an interface

//Interface: solves the problem of defining a common contract without forcing unrelated classes to share implementation or inheritance.
    1. Interface gives us the contract
    2. Enables polymorphism
    3. Reduces coupling between classes
    4. Allows multiple contracts
    5. unrelated classes

    Interface -> WHAT should be done -> Implementation -> HOW it is done

> Why not just use an abstract class?
- Java has single class inheritance 
- but cannot extend another class at the same time
** Interfaces allow a class to follow multiple contracts **

> Interface types
   |
   ├── Normal       → Multiple abstract methods
   ├── Functional   → Exactly ONE abstract method also called SAM (Single Abstract Method)
   └── Marker       → ZERO abstract methods

>StreamAPI
- Stream is a way to process elements of a collection as a pipeline
   Stream API
   |
   ├── stream()       → create stream
   ├── filter()       → select elements
   ├── map()          → transform elements
   ├── sorted()       → sort
   ├── distinct()     → remove duplicates
   ├── limit()        → take first N
   ├── skip()         → skip first N
   ├── reduce()       → combine into one result
   ├── collect()      → convert result to collection
   ├── forEach()      → perform action on each
   └── count()        → count elements

>Map, Filter, Reduce, Sorted

| Method     | Purpose                            | Returns      |
| ---------- | ---------------------------------- | ------------ |
| map()      | Transform each element             | Stream       |
| filter()   | Select elements based on condition | Stream       |
| reduce()   | Combine elements into one result   | Single value |
| sorted()   | Sort elements                      | Stream       |

>Record
- Special type of class
- Mainly for storing data
- Less boilerplate
- Immutable components
Automatically provides: constructor + accessors + equals + hashCode + toString

>Sealed Class: allows us to restrict which classes can inherit from it. (restrict inheritance)
- A class extending a sealed class must declare how its inheritance continues.
  It can be:
    final     → cannot be extended further
    sealed    → restricts its own subclasses
    non-sealed → removes the restriction
- permits → specifies allowed subclasses

>Var => Local Variable Type Inference: lets the compiler infer the type of a local variable from its value, so we don't need to write the type explicitly.
 Important Rules:
    - Only for local variables: can use it only inside methods, constructors, and local blocks.
    - Must be initialized
    - var is not a keyword: It's a reserved type name. So we can even use it as a variable name
    - Cannot be used for method parameters, return types, or fields.
