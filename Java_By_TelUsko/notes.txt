//JVM Stack & Heap
Java memory can be broadly understood using Stack and Heap.
JVM Memory
│
├── Stack
│   └── Method calls + local variables + references
│
└── Heap
    └── Objects + instance fields

Example:
class Student {
    int age;
    String name;
}

public class Main {
    public static void main(String[] args) {

        int x = 10;

        Student s = new Student();
        s.age = 25;
        s.name = "Sunanda";
    }
}    

Conceptually:
STACK                          HEAP

main() frame                   Student object
┌───────────────┐             ┌───────────────┐
│ x = 10        │             │ age = 25      │
│ s ────────────┼────────────►│ name ──────────┼──► "Sunanda"
└───────────────┘             └───────────────┘

- Stack → method execution and local variables/references.
- Heap → objects created using new and their instance fields.
- s is a reference variable in the main() stack frame.
- The Student object referred to by s is in the heap.
- age is an int, but because it is an instance field, it is part of the Student object on the heap.
- When a method finishes, its stack frame is removed.
- Objects with no reachable references can later be reclaimed by Garbage Collection (GC).

//Access Modifiers
1. Private => accessible only inside the class where it is declared.
2. Protected => Same package → protected is accessible. Different package → accessible to subclasses
3. Default => can be accessed within the same class and anywhere in the same package. 
              also called package-private access.

                    private   default   protected   public
------------------------------------------------------------
Same Class             YES       YES        YES       YES
Same Package           NO        YES        YES       YES
Different Package
  - Subclass            NO        NO         YES       YES
  - Non-Subclass        NO        NO         NO        YES
------------------------------------------------------------


// toString(), equals(), hashCode()
> toString()
→ Default: ClassName@hex(hashCode())
→ Override when you want meaningful object output

> equals()
→ Default: compares references (this == obj)
→ Override when you want logical/value comparison

> hashCode()
→ Default: object-based hash value
→ Override when equals() is overridden
→ Used by HashMap / HashSet

//Upcasting & Downcasting
Upcasting => Child → Parent, Automatic, Usually safe

Downcasting => Parent → Child, Explicit cast required, Can cause ClassCastException

// Boxing & Unboxing
Boxing: Primitive → Wrapper
Unboxing: Wrapper → Primitive
